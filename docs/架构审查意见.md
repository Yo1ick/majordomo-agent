## 一、已修复的 Bug

### Bug 1：营养素字段精度丢失

**位置**：`meal_foods` 表、`nutrition_daily` 表  
**问题**：`protein_g`、`carbs_g`、`fat_g`、`amount_g` 定义为 `INTEGER`，但营养素常有小数（如脂肪 3.6g），整数存储会截断精度。  
**修复**：改为 `REAL`。已在 schema.sql 中修正。

### Bug 2：family_monthly_expense 视图无法正确聚合

**位置**：三.6 多用户支持 → 家庭聚合视图  
**问题**：
```sql
-- 错误：occurred_at 是精确时间戳，每行都不同，GROUP BY 后每行都是独立一组
GROUP BY fm.family_id, e.occurred_at
```
**修复**：
```sql
-- 正确：按年月聚合
GROUP BY fm.family_id, strftime('%Y-%m', e.occurred_at)
```
已在 schema.sql 中修正。

## 二、优化建议

### 建议 1：assets 表双维度混用
`current_amount`（金额/分）和 `quantity`（数量）同在一张表，不同 type 用不同字段，查询时依赖 type 区分，容易出错。  
建议加 CHECK 约束：
```sql
CHECK (
  (type IN ('cash','investment') AND current_amount IS NOT NULL) OR
  (type IN ('ingredient','consumable','electronics') AND quantity IS NOT NULL)
)
```

### 建议 2：目录结构调整
```
workspace/
├── agents/
├── data/
├── docs/          ← 新增，存 .md 规范文档
│   ├── dedup-strategy.md
│   ├── message-protocol.md
│   └── category-mapping.md
├── scripts/
├── tests/         ← 新增
└── config/        ← 新增，存环境配置
```
原 `lib/` 目录里放的是 Markdown 文档，语义上应归入 `docs/`。

### 建议 3：备份加异地策略
现有方案只有本地 sqlite3 backup，Mac Mini 硬盘故障会导致数据全丢。  
建议在 backup-db.sh 里追加一步同步到 iCloud Drive 或外置盘：
```bash
cp "$BACKUP_FILE" ~/Library/Mobile\ Documents/com~apple~CloudDocs/Backups/
```

### 建议 4：本地 API 最低限度的安全
哪怕只绑定 localhost 也要明确：
```
HOST=127.0.0.1  # 禁止局域网访问
```
或加简单 API Key Header 验证，防止局域网内其他设备误访问。

### 建议 5：pending_confirmations 过期处理
表有 `expires_at` 字段，但方案中未定义过期后行为。建议明确：
- 过期自动变更 status → `expired`
- 对应的 Feishu 卡片推送"已超时，请重新发送"
- cron 每小时扫描一次过期记录
