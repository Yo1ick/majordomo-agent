## 一、阻塞性问题（必须先回答）

### Q1：Agent 框架选型

文档写 "OpenClaw + 飞书 + SQLite"，OpenClaw 是 NanoClaw 的另一个名字，还是笔误？

**影响**：整个代码骨架、Agent 定义方式、工具注册方式都取决于此。  
**需要确认**：最终用什么框架？如果不用现成框架，是否纯 Python 手写 Agent 编排？

---

### Q2：飞书 Bot 接入方式

两种路线：

| 方案 | 优点 | 缺点 |
|------|------|------|
| 自建 HTTP Server + Webhook | 完全可控，消息实时 | 需要常驻进程，需处理签名验证 |
| 飞书卡片机器人（低代码） | 搭建快，自带 UI 交互 | 灵活度低，复杂流程难做 |

**需要确认**：选哪个？是否已经有飞书开发者账号和 App？

---

### Q3：OCR 方案

Bill Parser 的核心依赖。选项：

| 方案 | 准确率 | 成本 | 隐私 |
|------|--------|------|------|
| 飞书原生图片识别 | 中 | 免费 | 数据在飞书 |
| 百度 OCR / 腾讯 OCR | 高 | 按量付费 | 数据上传第三方 |
| Google Vision | 高 | 按量付费 | 数据出境 |
| 本地模型（Gemma/PaddleOCR） | 中-高 | 免费 | 数据不出本机 |
| 直接发图片给 Claude/Gemini 多模态 | 高 | 按量付费 | 数据上传 |

**需要确认**：倾向哪个？是否在意数据隐私（账单上传第三方）？
